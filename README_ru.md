# spec-debate — дебаты двух моделей над планом решения задачи

Скилл для **Claude Code**. В каждом раунде **обе модели независимо предлагают улучшения** — Claude
и **второй ИИ-ревьюер**, — а Claude выступает **редактором с правом вето**: проверяет каждое
предложение (и своё, и ревьюера), оставляет только то, что реально улучшает, остальное аргументированно
отклоняет.

**Ревьюер — один из трёх харнессов**, выбирается по тому, как ты просишь:

- **OpenAI Codex** — модели GPT (по умолчанию);
- **opencode** — open-source модели через `opencode run`, напр. **kimi**, **glm** (а также deepseek, qwen);
- **свежий инстанс Claude** (`claude -p`) — **opus** / **sonnet**, независимый от текущей сессии.

Назови модель или харнесс — *«спроси кими»*, *«пусть glm раскритикует»*, *«посоветуйся с кодексом»*,
*«пусть опус оценит»* — и скилл направит туда (последняя версия этой модели). Без имени — дефолт: первый
установленный из **codex → opencode → claude**. Имя модели триггерит, только когда это *ревью* артефакта:
*«перепиши на kimi»* — это задача, не ревью, и не срабатывает.

Улучшается **всегда спека**, и зайти можно четырьмя способами:

- **задача** → Claude пишет спеку решения и дебатит её;
- **код для доработки** → Claude пишет *спеку модификаций*; сам код во время дебата не трогается —
  он применяется потом, отдельным шагом;
- **готовая спека / план / дизайн** → берётся как есть;
- **идея / тезис / утверждение** → Claude пишет короткую position-спеку (узкая однопроходная версия остаётся prompt-only, без файла).

Можно и просто «взять второе мнение» по узкому вопросу на ходу — скилл прогонит один
**prompt-only** проход и вернёт независимый разбор (проверенный Claude) без сохранения состояния.
Решишь продолжить — материализует файл спеки и перейдёт в стандартный режим дебатов.

> Критик, которого слушаются всегда, — это просто второй автор.
> Критик, с которым спорят, даёт результат лучше, чем каждая модель поодиночке.

По умолчанию один вызов = один раунд: предложения → вето → правки → отчёт → сохранённое
состояние (`.<имя>.debate-state.json` рядом с файлом). Нужно несколько раундов — вызови скилл ещё раз
(продолжит с того места, где остановились), либо попроси сразу: «прогони 3 раунда» или «гоняй, пока не
останется значимых замечаний». Зафиксированные находки передаются ревьюеру, чтобы он не поднимал их
заново. Зашитый принцип — результат **лучше**, а не **больше**: скилл сопротивляется разрастанию
сложности.

## Требования

- **Claude Code** (CLI от Anthropic).
- **Хотя бы один харнесс-ревьюер** — дебату нужен *независимый* второй движок. Ставь любой (или
  несколько); скилл использует то, что есть:
  - **Codex** (дефолт): `npm install -g @openai/codex`, затем `codex login status` (иначе `codex login`);
  - **opencode**: по его докам, с настроенным провайдером (`opencode models` должен быть непустым);
  - **Claude**: ничего ставить не нужно — свежий `claude -p` доступен всегда и служит финальным фолбэком.
- **`bash`** в PATH (плюс **`pgrep`** для codex-пути — он держит один `codex exec` за раз).
  Есть по умолчанию в **macOS и стандартных Linux**. **Windows: используйте WSL2** — нативный Windows не поддержан.

## Данные и приватность

По умолчанию spec-debate отправляет **полный текст спеки** (и файлы, которые Codex прочитает в рабочей
папке) провайдеру ревьюера: **OpenAI** (Codex), **провайдеру opencode-модели** — напр. Moonshot для
kimi, Zhipu для glm — или **Anthropic** (свежий Claude). Скилл называет разрешённого провайдера в
отчёте; если фолбэк сменил провайдера относительно названного тобой — сообщает об этом. Для
чувствительного материала включи **privacy-режим** («privacy mode» / «не отправляй код»): тогда ревьюер
получает только одобренную абстрактную сводку — с пометкой об ограниченном доверии, — либо проход
отменяется. Не клади секреты в спеку и не запускай дефолтный режим на данных, которые нельзя передавать
этому провайдеру.

> **О совпадении моделей.** Когда ревьюер — свежий Claude твоей же модели, свежий инстанс убирает
> якорение, но не коррелированные слепые зоны — для настоящей кросс-провайдерной независимости бери
> **codex** или **opencode**. (Дефолт — codex, так что это исключение.)

## Установка

Эта версия поставляется в плагине **`agentic-tools`** в маркетплейсе **`omd-plugins`**. В Claude Code один раз добавь
маркетплейс, затем поставь плагин:

```
/plugin marketplace add git@gitlab.sol.onetick.com:solutions/ml-ops/ai-plugins.git
/plugin install agentic-tools@omd-plugins
```

Скилл доступен как `/spec-debate`. Если раньше клонировал его вручную в
`~/.claude/skills/spec-debate/`, удали ту копию, чтобы не было двойной регистрации.

SKILL.md находит вспомогательные скрипты относительно собственной папки, поэтому работает там, где
установлен плагин. Структура:

```
spec-debate/
├── SKILL.md
├── README.md
├── README_ru.md
├── LICENSE
├── scripts/
│   ├── run_critique.sh          # дисперчер: codex | opencode | claude
│   └── run_codex_critique.sh    # закалённый codex-адаптер (вызывается дисперчером)
└── evals/
    └── evals.json
```

## Использование

```
/spec-debate                       # план/спека из текущего диалога; дефолтный ревьюер (codex)
/spec-debate path/to/spec.md       # явный путь
спроси кими по этому плану           # направить в opencode / kimi
пусть glm раскритикует spec.md       # направить в opencode / glm
посоветуйся с опусом по плану         # свежий инстанс Claude
/spec-debate path --max            # максимум глубины рассуждений (дефолт high; медленнее) — codex→xhigh, opencode→max
```

Уровни усилия — **low / medium / high / max**, маппятся под харнесс (у claude ручки усилия нет). Хочешь
ещё раунд — вызови снова, подхватит состояние. Можно дописать свои инструкции: «прогони 3 раунда» или
«гоняй, пока не останется значимых замечаний».

## Как это устроено (коротко)

1. **Выбирает ревьюера, режим и спеку.** Step 0 определяет харнесс + модель (см. выше); быстрый осмотр
   объёма решает между одно-проходным *prompt-only* советом и *итерируемой спекой*; для задачи или кода
   Claude сначала пишет спеку / спеку модификаций по минимальной форме (goal, non-goals, ограничения,
   acceptance-критерии, …) и называет её **тип и высоту**.
2. **Обе модели предлагают независимо.** Claude формирует свой список улучшений; ревьюер предлагает
   свой, не видя списка Claude (чтобы не якориться). Дисперчер `run_critique.sh <harness>` передаёт
   промпт через **stdin** — документ не попадает в аргументы команды, — делает preflight CLI и (для
   codex-пути) запускает по одному `codex exec` за раз. *(+1 проход, где ревьюер оппонирует списку
   Claude — по запросу (`thorough`) или автоматически, когда собственные находки Claude тянут на major.)*
3. **Сливает с правом вето.** Оба списка — ревьюера и собственный Claude — проходят одну процедуру:
   проверить, что находка реальна (перечитать раздел, грепнуть упомянутые файлы/числа), оценить пользу
   на высоте спеки, затем принять / частично / отклонить с однострочной причиной (отклонённые свои —
   тоже в отчёт).
4. **Вносит точечные правки**, затем перечитывает изменённое на самосогласованность.
5. **Пишет отчёт** (принято / частично / отклонено, с указанием ревьюера) и **сохраняет состояние**,
   рекомендуя СТОП, когда остаются лишь минорные находки. Для спеки модификаций применение к коду —
   отдельный пост-дебатный шаг, в отчёте отдельно от дебата.
